# CRUD Operations with FastAPI and SQLAlchemy

## Introduction to CRUD

CRUD stands for **Create, Read, Update, and Delete**. These are the four fundamental operations performed on data stored in a database.

In a FastAPI application, CRUD operations are implemented using API endpoints that communicate with a database through SQLAlchemy.

Each operation performs a specific task:

1. **Create:** Inserts new records into the database.
2. **Read:** Retrieves existing records from the database.
3. **Update:** Modifies existing records in the database.
4. **Delete:** Removes records from the database.

In this implementation, SQLite is used as the database, SQLAlchemy is used to interact with the database, and FastAPI is used to expose the CRUD operations through API endpoints.

### Understanding the CRUD Operations

| Operation | HTTP Method | Purpose |
|---|---|---|
| Create | POST | Insert new data |
| Read | GET | Retrieve existing data |
| Update | PUT | Modify existing data |
| Delete | DELETE | Remove existing data |

# 1. CREATE – Insert Data

## 1.1 What is CREATE?

The CREATE operation is used to insert new records into a database table.

Whenever a user submits new information, the application receives the data and stores it in the database.

For example, consider a Todo application where users can create tasks.

A user may submit the following information:

```json
{
    "title": "Learn FastAPI",
    "completed": "False"
}
```

The application creates a new record in the `todos` table.

The database may look like this after inserting the record:

| id | title | completed |
|---|---|---|
| 1 | Learn FastAPI | False |

The `id` is automatically generated by SQLite when a value is not explicitly provided for the integer primary key.

## 1.2 CREATE API

```python
@app.post("/todos")
def create_todo(title: str, db: Session = Depends(get_db)):
    todo = Todo(title=title, completed="False")

    db.add(todo)
    db.commit()
    db.refresh(todo)

    return {
        "message": "Todo created",
        "data": todo
    }
```

### Understanding the Code Step by Step

**1. Defining the POST Endpoint**

```python
@app.post("/todos")
```

The `@app.post()` decorator creates a POST API endpoint.

- POST is an HTTP method generally used to submit new data.
- `/todos` is the endpoint path.

When a client sends a POST request to `/todos`, FastAPI executes the `create_todo()` function.

**2. Receiving the Todo Title**

```python
def create_todo(title: str, db: Session = Depends(get_db)):
```

The function accepts two parameters.

- `title: str`: Receives the todo title as a string. Since it is a simple parameter and is not part of the path, FastAPI treats it as a query parameter by default.
- `db: Session = Depends(get_db)`: Receives a database session through FastAPI dependency injection.

The `get_db()` function creates a session and provides it to the endpoint.

**3. Creating a Todo Object**

```python
todo = Todo(title=title, completed="False")
```

This creates a new Python object using the `Todo` SQLAlchemy model.

The model represents the `todos` database table.

The submitted title is assigned to the `title` column, and the completion status is initially set to `"False"`.

At this stage, the object is created in Python memory. It has not yet been permanently inserted into the database.

**4. Adding the Object to the Session**

```python
db.add(todo)
```

The `add()` method adds the newly created object to the SQLAlchemy session.

It marks the object as pending insertion.

The database INSERT operation is normally issued when the session is flushed, which can happen during `commit()`.

**5. Committing the Changes**

```python
db.commit()
```

The `commit()` method commits the current database transaction.

It makes the insertion permanent in the database.

Without committing, the changes may not be permanently saved.

**6. Refreshing the Object**

```python
db.refresh(todo)
```

The `refresh()` method reloads the object from the database.

It is useful when the database generates values automatically, such as the primary key.

For example, after inserting a todo, SQLite may generate:

```text
id = 1
```

The refresh operation ensures that the Python object contains the latest database values.

**7. Returning the Response**

```python
return {
    "message": "Todo created",
    "data": todo
}
```

The endpoint returns a success message along with the created todo record.

FastAPI converts the response into JSON.

### CREATE API Execution Flow

1. The client sends a POST request to `/todos`.
2. FastAPI receives the todo title.
3. `Depends(get_db)` provides a database session.
4. A new `Todo` object is created.
5. `db.add()` adds the object to the session.
6. `db.commit()` saves the new record.
7. `db.refresh()` reloads the inserted record.
8. FastAPI returns the response.
9. The database dependency closes the session after request processing.

# 2. READ – Fetch Data

## 2.1 What is READ?

The READ operation is used to retrieve existing records from a database without modifying them.

For example, in a Todo application, users may want to:

- View all their todo tasks.
- Retrieve a particular task using its ID.
- Check whether a task has been completed.

There are two READ operations in this implementation:

1. READ ALL – Fetches all records.
2. READ ONE BY ID – Fetches a particular record using its unique ID.

## 2.2 READ ALL – Fetch All Records

```python
@app.get("/todos")
def get_todos(db: Session = Depends(get_db)):
    todos = db.query(Todo).all()

    return {
        "total": len(todos),
        "data": todos
    }
```

### Understanding the Code Step by Step

**1. Defining the GET Endpoint**

```python
@app.get("/todos")
```

The `@app.get()` decorator defines a GET endpoint.

GET is an HTTP method used to retrieve information from a server.

When a client sends a GET request to `/todos`, FastAPI executes the `get_todos()` function.

**2. Receiving the Database Session**

```python
db: Session = Depends(get_db)
```

This parameter tells FastAPI to provide a database session using the `get_db()` dependency.

The session is used to communicate with the database.

**3. Retrieving All Records**

```python
todos = db.query(Todo).all()
```

This is the main database query.

Understanding it requires looking at two methods.

**db.query(Todo)**

The `query()` method creates a SQLAlchemy query for the specified model.

Here, `Todo` represents the `todos` database table.

Therefore:

```python
db.query(Todo)
```

means that the application wants to retrieve records from the `todos` table.

**.all()**

The `all()` method executes the query and returns all matching records as a Python list.

For example, if the database contains three records, the result may look conceptually like this:

```python
[
    Todo(id=1, title="Learn FastAPI", completed="False"),
    Todo(id=2, title="Learn SQLAlchemy", completed="False"),
    Todo(id=3, title="Practice CRUD", completed="True")
]
```

If the table is empty, `.all()` returns an empty list.

**4. Returning the Total Number of Records**

```python
"total": len(todos)
```

The `len()` function returns the number of elements in a list.

For example, if three todo records are retrieved:

```python
len(todos) = 3
```

Therefore, the response contains the total number of records.

**5. Returning the Retrieved Data**

```python
"data": todos
```

Returns all the retrieved todo records as part of the response.

### READ ALL Execution Flow

1. The client sends a GET request to `/todos`.
2. FastAPI calls the `get_todos()` function.
3. A database session is provided through `Depends(get_db)`.
4. `db.query(Todo)` creates a query for the Todo model.
5. `.all()` retrieves all matching records.
6. `len(todos)` calculates the total number of records.
7. FastAPI returns the total count and retrieved data.
8. The database session is closed after request processing.

## 2.3 READ ONE BY ID – Fetch a Particular Record

```python
@app.get("/todos/{todo_id}")
def get_todo(todo_id: int, db: Session = Depends(get_db)):
    todo = db.query(Todo).filter(Todo.id == todo_id).first()

    if not todo:
        raise HTTPException(
            status_code=404,
            detail=f"todo with id {todo_id} not found"
        )

    return {
        "message": f"todo with id {todo_id} is retrieved",
        "data": todo
    }
```

This endpoint retrieves a particular todo record using its ID.

### Understanding the Code Step by Step

**1. Defining the Endpoint**

```python
@app.get("/todos/{todo_id}")
```

This creates a GET endpoint with a path parameter named `todo_id`.

For example:

```text
GET /todos/2
```

Here, `2` is the requested todo ID.

**2. Receiving the Path Parameter**

```python
todo_id: int
```

The `todo_id` parameter receives the ID from the URL.

The `int` type annotation tells FastAPI to validate and convert the path parameter into an integer.

**3. Querying the Database**

```python
todo = db.query(Todo).filter(Todo.id == todo_id).first()
```

This statement retrieves a particular record.

It contains three important operations.

**db.query(Todo)**

Creates a query for the `Todo` model.

**.filter()**

The `filter()` method adds a condition to the query.

Here:

```python
Todo.id == todo_id
```

checks whether the database record's ID matches the ID supplied in the URL.

For example, if `todo_id = 2`, the condition becomes:

```text
Todo.id == 2
```

Only records satisfying this condition are considered.

**.first()**

The `first()` method executes the query and returns the first matching record.

- If a matching record exists, it returns the corresponding Todo object.
- If no matching record exists, it returns `None`.

This is why `.first()` is useful when retrieving one particular record.

**4. Handling Missing Records**

```python
if not todo:
    raise HTTPException(
        status_code=404,
        detail=f"todo with id {todo_id} not found"
    )
```

This condition checks whether the requested record exists.

If `.first()` returns `None`, the condition becomes true.

The application raises an HTTP exception with status code 404.

**HTTPException:**

`HTTPException` is provided by FastAPI and is used to return an HTTP error response.

**status_code=404:**

404 means Not Found.

It indicates that the requested resource does not exist.

**detail:**

Provides a descriptive error message.

For example, when the user requests ID 4 and that record does not exist:

```json
{
    "detail": "todo with id 4 not found"
}
```

**5. Returning the Retrieved Record**

```python
return {
    "message": f"todo with id {todo_id} is retrieved",
    "data": todo
}
```

If the record exists, the endpoint returns a success message and the retrieved todo data.

### READ ONE BY ID Execution Flow

1. The client sends a GET request such as `/todos/2`.
2. FastAPI extracts the ID from the URL.
3. A database session is injected into the endpoint.
4. `db.query(Todo)` creates a query for the Todo model.
5. `.filter()` applies the ID condition.
6. `.first()` retrieves the first matching record.
7. If no record exists, HTTPException returns a 404 response.
8. If the record exists, the endpoint returns the retrieved data.
9. The database session is closed after request processing.

## 2.4 Understanding Important SQLAlchemy READ Methods

| Method | Purpose | Result |
|---|---|---|
| `query()` | Creates a query for a model | SQLAlchemy query |
| `filter()` | Adds a filtering condition | Filtered query |
| `first()` | Retrieves the first matching record | Object or `None` |
| `all()` | Retrieves all matching records | List of objects |

### Difference Between first() and all()

**first():**

Returns only the first matching record.

```python
todo = db.query(Todo).filter(Todo.id == 2).first()
```

**all():**

Returns all matching records.

```python
todos = db.query(Todo).all()
```

# 3. UPDATE – Update Data

## 3.1 What is UPDATE?

The UPDATE operation is used to modify existing records in a database.

For example, consider a Todo application where a user initially creates a task:

| id | title | completed |
|---|---|---|
| 1 | Learn Python | False |

Later, the user decides to change the title to `Learn FastAPI`.

After updating:

| id | title | completed |
|---|---|---|
| 1 | Learn FastAPI | False |

The record is modified without creating a new row.

## 3.2 UPDATE API

```python
@app.put("/todos/{todo_id}")
def update_todo(todo_id: int, title: str, db: Session = Depends(get_db)):
    todo = db.query(Todo).filter(Todo.id == todo_id).first()

    if not todo:
        raise HTTPException(
            status_code=404,
            detail=f"todo with id {todo_id} not found"
        )

    todo.title = title
    db.commit()
    db.refresh(todo)

    return {
        "message": "Db got updated",
        "data": todo
    }
```

### Understanding the Code Step by Step

**1. Defining the PUT Endpoint**

```python
@app.put("/todos/{todo_id}")
```

The `@app.put()` decorator creates a PUT endpoint.

PUT is an HTTP method commonly used to update an existing resource.

Here, the endpoint receives the ID of the record that needs to be updated.

**2. Receiving the Parameters**

```python
def update_todo(todo_id: int, title: str, db: Session = Depends(get_db)):
```

The function receives three parameters:

- `todo_id`: Identifies the record that needs to be updated.
- `title`: Contains the new title.
- `db`: Receives the database session through dependency injection.

Both `todo_id` and `title` are simple parameters. In this implementation, `todo_id` comes from the URL path and `title` is received as a query parameter.

**3. Retrieving the Existing Record**

```python
todo = db.query(Todo).filter(Todo.id == todo_id).first()
```

Before updating a record, the application must first retrieve the existing record.

- `query(Todo)` creates a query for the Todo model.
- `filter()` checks for the matching ID.
- `first()` retrieves the matching record.

**4. Checking Whether the Record Exists**

```python
if not todo:
    raise HTTPException(
        status_code=404,
        detail=f"todo with id {todo_id} not found"
    )
```

If the requested record does not exist, the application returns a 404 Not Found error.

This prevents the application from attempting to update a nonexistent record.

**5. Updating the Record**

```python
todo.title = title
```

This statement changes the title attribute of the retrieved Todo object.

For example:

```text
Existing title: Learn Python
New title: Learn FastAPI
```

The new title is assigned to the object.

SQLAlchemy tracks changes made to objects associated with its session.

**6. Committing the Update**

```python
db.commit()
```

The `commit()` method saves the modified record permanently in the database.

SQLAlchemy detects the changed title and generates the required SQL UPDATE statement during the transaction.

**7. Refreshing the Object**

```python
db.refresh(todo)
```

The `refresh()` method reloads the latest database values into the Python object.

This ensures that the returned object reflects the current database state.

**8. Returning the Response**

```python
return {
    "message": "Db got updated",
    "data": todo
}
```

Returns a success message and the updated record.

### UPDATE API Execution Flow

1. The client sends a PUT request with the todo ID and new title.
2. FastAPI extracts the path and query parameters.
3. A database session is injected.
4. The existing record is retrieved using its ID.
5. The application checks whether the record exists.
6. If it does not exist, a 404 error is returned.
7. If it exists, the title is modified.
8. `db.commit()` saves the update.
9. `db.refresh()` reloads the updated record.
10. The endpoint returns the updated data.
11. The database session is closed after request processing.

## 3.3 Why is db.refresh() Used in UPDATE?

After modifying an object, `db.commit()` saves the changes to the database.

The `db.refresh()` method then reloads the object from the database.

It ensures that the returned object contains the latest database values, including any values generated or modified by the database.

For this simple title update, refreshing is often optional, but it is useful when the application needs the latest database state.

# 4. DELETE – Remove Data

## 4.1 What is DELETE?

The DELETE operation is used to remove an existing record from a database table.

For example, consider a Todo application containing the following records:

| id | title | completed |
|---|---|---|
| 1 | Learn Python | False |
| 2 | Learn FastAPI | False |
| 3 | Practice SQLAlchemy | True |

If the user wants to delete the record with ID 2, the application removes that record.

After deletion:

| id | title | completed |
|---|---|---|
| 1 | Learn Python | False |
| 3 | Practice SQLAlchemy | True |

The other records remain unchanged.

## 4.2 DELETE API

```python
@app.delete("/todos/{todo_id}")
def delete_todo(todo_id: int, db: Session = Depends(get_db)):
    todo = db.query(Todo).filter(Todo.id == todo_id).first()

    if not todo:
        raise HTTPException(
            status_code=404,
            detail=f"todo with id {todo_id} not found"
        )

    db.delete(todo)
    db.commit()

    return {
        "message": "todo deleted"
    }
```

### Understanding the Code Step by Step

**1. Defining the DELETE Endpoint**

```python
@app.delete("/todos/{todo_id}")
```

The `@app.delete()` decorator defines an endpoint used to delete a particular record.

The ID is supplied through the URL.

For example:

```text
DELETE /todos/2
```

This request asks the application to delete the record whose ID is 2.

**2. Receiving the Parameters**

```python
def delete_todo(todo_id: int, db: Session = Depends(get_db)):
```

The function receives:

- `todo_id`: The ID of the record to be deleted.
- `db`: The database session provided through dependency injection.

**3. Retrieving the Record**

```python
todo = db.query(Todo).filter(Todo.id == todo_id).first()
```

Before deleting a record, the application first retrieves it from the database.

The query searches for the record whose ID matches the supplied `todo_id`.

If the record exists, the Todo object is returned.

Otherwise, `.first()` returns `None`.

**4. Checking Whether the Record Exists**

```python
if not todo:
    raise HTTPException(
        status_code=404,
        detail=f"todo with id {todo_id} not found"
    )
```

If the record does not exist, the application returns a 404 Not Found error.

This prevents the application from attempting to delete a nonexistent record.

**5. Deleting the Record**

```python
db.delete(todo)
```

The `delete()` method marks the retrieved object for deletion from the database.

The actual deletion is committed to the database in the next step.

**6. Committing the Deletion**

```python
db.commit()
```

The `commit()` method permanently saves the deletion operation.

After the transaction is committed, the record is removed from the database.

**7. Returning the Response**

```python
return {
    "message": "todo deleted"
}
```

Returns a success message indicating that the record has been deleted.

### DELETE API Execution Flow

1. The client sends a DELETE request with the todo ID.
2. FastAPI extracts the ID from the URL.
3. A database session is injected.
4. The application retrieves the record using its ID.
5. It checks whether the record exists.
6. If the record does not exist, a 404 error is returned.
7. If it exists, `db.delete()` marks the record for deletion.
8. `db.commit()` permanently saves the deletion.
9. A success response is returned.
10. The database session is closed after request processing.

## 4.3 Why is db.refresh() Not Used in DELETE?

In CREATE and UPDATE operations, `db.refresh()` can be used to reload an existing database record.

However, in DELETE, the record is removed from the database after `db.commit()`.

Therefore, refreshing the deleted object is unnecessary and can cause an error because the database record no longer exists.

The correct deletion sequence is:

```python
db.delete(todo)
db.commit()
```

Do not call `db.refresh(todo)` after committing the deletion.

# 7. Important SQLAlchemy Methods Used in CRUD

| Method | Purpose |
|---|---|
| `db.add()` | Adds a new object to the session |
| `db.query()` | Creates a query for an ORM model |
| `.filter()` | Adds a condition to a query |
| `.first()` | Retrieves the first matching record |
| `.all()` | Retrieves all matching records |
| `db.commit()` | Commits transaction changes |
| `db.refresh()` | Reloads an object from the database |
| `db.delete()` | Marks an object for deletion |
| `db.close()` | Closes the database session |

### Understanding the Methods Through CRUD

- CREATE uses `add()`, `commit()`, and `refresh()`.
- READ ALL uses `query()` and `all()`.
- READ ONE uses `query()`, `filter()`, and `first()`.
- UPDATE uses `query()`, `filter()`, `first()`, `commit()`, and optionally `refresh()`.
- DELETE uses `query()`, `filter()`, `first()`, `delete()`, and `commit()`.

# 8. Important Interview Questions

## General CRUD Questions

### 1. What is CRUD?

CRUD stands for Create, Read, Update, and Delete. These are the four fundamental operations used to manage data in a database.

### 2. Which HTTP methods are commonly used for CRUD operations?

- POST – Create.
- GET – Read.
- PUT – Update.
- DELETE – Delete.

### 3. What is the difference between POST and PUT?

POST is commonly used to create a new resource, whereas PUT is commonly used to update or replace an existing resource.

### 4. What is the difference between GET and POST?

GET is used to retrieve data from the server, whereas POST is commonly used to submit data to create a new resource.

### 5. What is the difference between PUT and PATCH?

PUT is generally used to replace or update a resource, whereas PATCH is used to apply a partial update to an existing resource.

## CREATE Questions

### 6. What is the purpose of db.add()?

`db.add()` adds a new ORM object to the SQLAlchemy session and marks it for insertion into the database.

### 7. Why is db.commit() used after db.add()?

`db.commit()` commits the transaction and permanently saves the new record in the database.

### 8. What is the purpose of db.refresh() after creating a record?

It reloads the newly inserted object from the database so that the Python object contains the latest database values, including generated values such as the primary key.

### 9. How is a primary key generated in this application?

The `id` column is defined as an `Integer` primary key. SQLite automatically assigns an integer ID when the application inserts a record without specifying an ID.

## READ Questions

### 10. What is the purpose of db.query()?

`db.query()` creates a SQLAlchemy query for the specified ORM model.

### 11. What is the difference between all() and first()?

`all()` retrieves all matching records and returns a list, whereas `first()` retrieves only the first matching record or returns `None` if no match exists.

### 12. What is the purpose of filter()?

`filter()` adds a condition to a database query to retrieve only records that satisfy the specified condition.

### 13. What happens if no matching record is found using first()?

The `first()` method returns `None` when no matching record exists.

### 14. Why is HTTPException used in READ ONE?

It is used to return an appropriate HTTP error response when the requested record does not exist.

### 15. What is HTTP 404?

HTTP 404 Not Found indicates that the requested resource could not be found on the server.

## UPDATE Questions

### 16. How does SQLAlchemy update an existing record?

The application retrieves the existing ORM object, modifies its attributes, and calls `db.commit()` to save the changes.

### 17. Why is the record retrieved before updating?

The application needs to identify the existing record and verify that it exists before modifying its attributes.

### 18. Is db.refresh() mandatory after updating?

No. It is optional when the application does not need to reload database-generated or database-modified values. It is useful when the latest database state is required.

### 19. What happens if an invalid ID is provided during an update?

If no matching record is found, the application raises an HTTPException with status code 404.

## DELETE Questions

### 20. What is the purpose of db.delete()?

`db.delete()` marks the specified ORM object for deletion from the database.

### 21. Why is db.commit() required after db.delete()?

It commits the deletion transaction, making the removal permanent in the database.

### 22. Why should db.refresh() not be used after deletion?

After the deletion is committed, the database record no longer exists. Refreshing the deleted object is unnecessary and can cause an exception.

### 23. What happens if a nonexistent ID is provided during deletion?

The application checks whether the record exists. If it does not, the endpoint raises HTTP 404 Not Found.

## FastAPI and SQLAlchemy Questions

### 24. What is Depends() in FastAPI?

`Depends()` is used for dependency injection. It allows FastAPI to provide resources such as database sessions to endpoint functions.

### 25. What is the purpose of get_db()?

`get_db()` creates a database session, provides it to the endpoint using `yield`, and closes it after request processing.

### 26. Why is the database session closed after every request?

Closing the session releases associated resources and prevents sessions from remaining open unnecessarily.

### 27. What is the difference between db.add() and db.commit()?

`db.add()` registers an object with the session for insertion, whereas `db.commit()` commits pending transaction changes to the database.

### 28. What happens if an exception occurs during a database transaction?

A failed transaction may need to be rolled back using `db.rollback()` before the session can be used for further database operations. The session dependency should also close the session during cleanup.

### 29. Can CRUD operations be implemented without SQLAlchemy?

Yes. CRUD operations can be implemented using database-specific Python libraries such as `sqlite3`. SQLAlchemy provides ORM and SQL toolkit functionality that simplifies database interaction.

### 30. What is the role of FastAPI in CRUD operations?

FastAPI exposes API endpoints, receives client requests, validates parameters, injects dependencies, and returns responses after the database operations are performed.
